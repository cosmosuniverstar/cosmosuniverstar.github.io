초보자를 위한 OSI 7 계층 및 네트워크 핵심 가이드: 개념부터 AWS 실전 적용까지

네트워크는 현대 IT 인프라를 지탱하는 혈관과 같습니다. 특히 클라우드(AWS) 환경으로 전환되면서 가상 네트워크(VPC)를 설계하고 보안 정책을 수립하기 위한 네트워크 기초 지식은 아키텍트에게 선택이 아닌 필수 역량이 되었습니다. 본 가이드에서는 복잡한 통신 과정을 표준화한 OSI 7 계층 모델을 중심으로, 이론이 실제 실무와 클라우드 환경에서 어떻게 작동하는지 시니어 아키텍트의 관점에서 깊이 있게 다루겠습니다.

---

## 1. 네트워크 통신의 표준, OSI 7 계층 모델의 이해

네트워크 통신은 수많은 하드웨어와 소프트웨어가 유기적으로 맞물려 돌아가는 복잡한 과정입니다. 국제표준화기구(ISO)는 이 과정을 명확히 이해하고 문제 발생 시 논리적인 지점을 찾아 해결할 수 있도록 **OSI 7 계층 모델(Open Systems Interconnection Model)**이라는 공통 언어를 제정했습니다.

이 모델은 데이터를 전송할 때 상위 계층에서 하위 계층으로 내려가며 각 단계의 제어 정보(헤더)를 덧붙이는 '캡슐화(Encapsulation)' 과정을 거칩니다. 반대로 수신 측에서는 1계층부터 7계층으로 올라가며 헤더를 제거하는 역캡슐화를 통해 원본 데이터를 복원합니다. 이러한 계층화된 구조는 각 계층이 독립적으로 기능하게 하여 기술적 유연성을 보장합니다.

### OSI 7 계층 핵심 요약

| 계층 | 명칭 | 데이터 단위 (PDU) | 핵심 역할 및 기능 | 주요 프로토콜 및 장비 |
|:----:|------|:-----------------:|-------------------|----------------------|
| 7 | 응용 (Application) | 데이터 (Data) | 사용자와 직접 상호작용, 서비스 제공 | HTTP, HTTPS, FTP, DNS |
| 6 | 표현 (Presentation) | 데이터 (Data) | 데이터 형식 변환, 암호화, 압축 | JPEG, MPEG, ASCII |
| 5 | 세션 (Session) | 데이터 (Data) | 통신 세션 수립, 유지 및 복구 관리 | NetBIOS, RPC |
| 4 | 전송 (Transport) | 세그먼트 (Segment) | 신뢰성 있는 전송, 포트 기반 프로세스 식별 | TCP, UDP |
| 3 | 네트워크 (Network) | 패킷 (Packet) | IP 주소 기반 최적 경로 설정 (라우팅) | IP, ICMP, 라우터 |
| 2 | 데이터 링크 (Data Link) | 프레임 (Frame) | 동일 네트워크 내 MAC 주소 기반 통신 | Ethernet, 스위치 |
| 1 | 물리 (Physical) | 비트 (Bit) | 전기적 신호 변환 및 물리 매체 전송 | 케이블, 허브, 리피터 |

전체적인 구조를 파악했으니, 이제 실제 통신이 시작되는 하위 계층의 물리적 장비와 주소 체계를 분석하겠습니다.

## 2. 하부 계층의 기초: 물리 계층(L1)과 데이터 링크 계층(L2)

로컬 네트워크 내에서 장치들이 물리적으로 연결되고 서로를 식별하는 과정은 네트워크의 근간입니다.

### L1 허브의 동작과 한계

**허브(Hub)**는 물리 계층(L1)에서 작동하며 들어온 신호를 단순히 복제하여 연결된 모든 포트로 뿌리는 브로드캐스팅 방식을 사용합니다. 목적지를 구분하지 못하기 때문에 불필요한 트래픽을 대량 유발하며, 여러 장치가 동시에 데이터를 보낼 경우 데이터 충돌(Collision)이 발생하여 성능이 급격히 저하됩니다. 이 때문에 현대 네트워크에서는 '더미 허브'로 취급되며 점차 자취를 감추고 있습니다.

### L2 MAC 주소와 통신 규약

데이터 링크 계층(L2)에서는 하드웨어 고유 식별자인 MAC 주소를 사용합니다. 48비트 길이의 이 주소는 제조사 식별 코드인 OUI와 제조사 할당 시리얼 번호로 구성됩니다. MAC 주소는 계층 구조가 없는 **물리적 주소(Flat Address)**이기에 대규모 네트워크 확장에 한계가 있으며, 장치 수가 많아지면 모든 장치에 신호가 도달하는 브로드캐스트 스톰(Broadcast Storm) 문제를 야기할 수 있습니다.

과거 유선 LAN 환경의 핵심 규약이었던 CSMA/CD는 다음과 같이 동작합니다.

1. **반송파 감지(Sense)**: 채널이 비어 있는지 확인합니다.
2. **다중 접속(Access)**: 채널이 비어 있으면 데이터를 전송합니다.
3. **충돌 감지(Detection)**: 전송 중 충돌이 감지되면 즉시 중단하고 **잼 신호(Jam Signal)**를 보내 다른 장치에 알린 뒤, 임의의 시간(백오프) 동안 대기 후 재전송합니다.

### 현대의 해결책: 스위치

오늘날은 허브 대신 **스위치(Switch)**를 사용합니다. 스위치는 MAC 주소를 학습하여 필요한 포트로만 데이터를 전달하며, 송수신이 동시에 가능한 전이중(Full-duplex) 통신을 지원하여 충돌 문제를 근본적으로 해결했습니다.

로컬 내 식별은 MAC 주소로 가능하지만, 전 세계적인 네트워크망으로 확장하기 위해서는 논리적인 주소 체계인 3계층의 IP가 필요합니다.

## 3. 네트워크 계층(L3): 논리적 주소와 최적의 경로 설정

네트워크 계층은 데이터 패킷이 여러 네트워크를 거쳐 발신지에서 최종 목적지까지 도달하도록 관리하는 전략적 요충지입니다.

### IP 주소의 체계와 IPv4 vs IPv6

IP는 네트워크 환경에 따라 변경 가능한 논리적 주소입니다. IPv4의 주소 고갈 문제를 해결하기 위해 등장한 IPv6는 주소 공간 확대뿐만 아니라 보안성도 강화되었습니다.

| 구분 | IPv4 | IPv6 |
|------|------|------|
| 주소 길이 | 32비트 (4바이트) | 128비트 (16바이트) |
| 표기법 | 10진수 (예: 192.168.0.1) | 16진수 (예: 2001:0db8::8a2e) |
| 보안성 | IPsec 선택 사항 | IPsec 표준 포함 (보안 강화) |
| 헤더 구조 | 가변적, 복잡한 옵션 필드 | 단순화된 고정 헤더 (처리 속도 향상) |

### 라우터와 라우팅의 핵심 원리

**라우터(Router)**는 라우팅 테이블을 참조하여 패킷을 보낼 최적의 경로를 결정합니다. 또한 각 링크의 최대 전송 단위인 MTU에 맞춰 패킷을 쪼개는 단편화(Fragmentation) 기능을 수행합니다. IP 프로토콜 자체는 비연결성 및 비신뢰성 특성을 가지므로, 경로 설정이라는 본연의 역할에 집중합니다.

### 비전공자를 위한 비유

- **IP 주소**: 편지 봉투에 적힌 최종 수신인의 '집 주소'
- **MAC 주소**: 택배가 이동하는 각 구간에서 물건을 건네받는 **'다음 단계 집배원'**의 식별 번호

IP 주소 체계를 더 효율적으로 사용하기 위해서는 주소를 유연하게 나누는 CIDR과 서브넷 마스크의 개념을 반드시 이해해야 합니다.

## 4. [심화] 주소 관리의 핵심: CIDR과 서브넷 마스크의 동작 원리

제한된 IP 자원을 효율적으로 분배하고 네트워크를 논리적으로 격리하는 기술은 현대 클라우드 아키텍처 설계의 기본입니다.

### 클래스 기반 할당의 한계와 CIDR의 등장

과거에는 A, B, C 클래스로 나누어 IP를 할당했습니다. 이 방식은 300개의 주소가 필요한 기업에 65,536개(B클래스)를 할당하여 65,236개의 주소를 낭비하게 만드는 심각한 부작용이 있었습니다. 이를 해결하고자 등장한 **CIDR(Classless Inter-Domain Routing)**은 클래스 개념을 없애고 필요한 만큼만 유연하게 블록을 할당합니다. (예: 300명 규모에 /23 프리픽스를 적용해 512개만 할당)

### 서브넷 마스크를 이용한 통신 경로 판단 (4단계 과정)

컴퓨터는 목적지 IP가 '내부'에 있는지 '외부(라우터행)'에 있는지 판단하기 위해 다음과 같이 AND 연산을 수행합니다. (예: 내 IP 192.168.1.100 / 서브넷 255.255.255.0 기준)

1. **나의 네트워크 주소 계산**: 내 IP와 내 서브넷 마스크를 AND 연산합니다. (결과: 192.168.1.0)
2. **상대방 네트워크 주소 계산**: 목적지 IP(예: 8.8.8.8)와 나의 서브넷 마스크를 AND 연산합니다. (결과: 8.8.8.0)
3. **네트워크 주소 비교**: 1단계와 2단계의 결과값(192.168.1.0 vs 8.8.8.0)을 비교합니다.
4. **전송 경로 결정**: 결과가 같으면 직접 전송하고, 다르면 외부 통로인 **기본 게이트웨이(라우터)**로 패킷을 보냅니다.

### CIDR 표기법(Prefix) 이해

/8, /16, /24 등 프리픽스 숫자가 커질수록 네트워크 주소 비트가 길어지므로, 네트워크 크기는 작아지고 할당 가능한 호스트 주소 수도 적어집니다. (/24는 256개, /28은 16개 주소 제공)

논리적 주소(IP)와 물리적 주소(MAC) 사이의 간극을 메워주는 보이지 않는 연결고리인 ARP 프로토콜에 대해 알아보겠습니다.

## 5. 주소 변환의 마법: ARP 프로토콜과 보안 위협

L3 IP 패킷이 실제 물리 장비인 L2 프레임으로 전달되려면 상대방의 MAC 주소를 반드시 알아야 합니다. 이 간극을 메우는 것이 **ARP(Address Resolution Protocol)**입니다.

### 라우터의 ARP 동작 5단계 (택배 기사 비유)

1. **경로 확인**: "B동으로 가려면 다음 담당 기사(Next Hop)에게 줘야겠군." (라우팅 테이블 조회)
2. **캐시 확인**: "그 기사의 무전기 번호(MAC)가 내 수첩에 있나?" (ARP 캐시 확인)
3. **요청 (Broadcast)**: 수첩에 없으면 단지 전체에 방송합니다. "B동 기사님, MAC 주소 좀 알려주세요!" (ARP Request)
4. **응답 (Unicast)**: 대상 기사만 답합니다. "제 MAC 주소는 XX입니다." (ARP Reply)
5. **저장 및 전송**: 수첩에 적고(캐시 업데이트) 패킷을 캡슐화하여 전달합니다.

### 보안 계층의 취약점 분석

ARP는 먼저 오는 응답을 조건 없이 신뢰하는 신뢰 기반(Trust-based) 프로토콜입니다. 공격자가 가짜 응답을 보내 데이터를 가로채는 **'ARP 스푸핑(Spoofing)'**을 시도하면, 통신 중간에서 정보를 탈취하는 **중간자 공격(MITM)**에 노출될 수 있습니다. 이를 방지하기 위해 스위치 수준에서 유효한 ARP만 허용하는 DAI(Dynamic ARP Inspection) 기능을 적용해야 합니다.

이제 데이터가 목적지까지 전달되는 경로를 확보했으므로, 데이터 전송의 '신뢰성'을 책임지는 전송 계층으로 올라가 보겠습니다.

## 6. 전송 계층(L4): 데이터 전송의 신뢰성과 TCP 3-Way Handshake

전송 계층은 데이터의 정확한 전달과 흐름 제어를 담당하여 애플리케이션의 안정적인 통신 환경을 보장합니다.

### TCP의 특징과 주요 사례

**TCP(Transmission Control Protocol)**는 신뢰성을 최우선으로 하는 연결 지향성 프로토콜입니다. 데이터가 순서대로 도착하도록 보장하고 흐름/혼잡 제어를 수행합니다. 웹 브라우징(HTTP), 이메일(SMTP), 파일 전송(FTP)처럼 데이터 유실이 치명적인 서비스에 필수적으로 사용됩니다.

### 신뢰의 시작: 3-Way Handshake

TCP는 통신 전 '전화 통화'와 같은 3단계 상호 확인 과정을 거칩니다.

1. **SYN**: "들리시나요? 연결하고 싶습니다." (클라이언트가 일련번호와 함께 요청)
2. **SYN+ACK**: "네, 잘 들립니다. 제 목소리도 들리시나요?" (서버가 응답 및 연결 확인)
3. **ACK**: "네, 잘 들립니다! 이제 데이터 보낼게요." (클라이언트가 최종 확인 후 통로 개설)

### 데이터 단위: 세그먼트(Segment)

L4의 PDU는 세그먼트입니다. 세그먼트 헤더에는 데이터의 신뢰성 제어 정보와 함께, 어떤 애플리케이션으로 데이터를 보낼지 결정하는 **포트 번호(Port Number)**가 포함됩니다.

지금까지 학습한 OSI 계층 이론이 실제 클라우드 서비스인 AWS에서는 어떤 형태로 구현되어 있는지 정리하며 마무리하겠습니다.

## 7. 실전 적용: AWS 네트워킹 서비스와 OSI 모델의 매핑

인프라 엔지니어에게 OSI 모델은 AWS의 복잡한 서비스를 분류하고 배치하는 전략적 지도와 같습니다.

- **L3 & L4 (네트워크/전송 계층) - NACL**: 네트워크 ACL은 서브넷 수준에서 IP 주소(L3)와 포트 번호(L4)를 기반으로 트래픽을 제어합니다. 상태를 저장하지 않는(Stateless) 방식이 특징입니다.
- **L4 (전송 계층) - 보안 그룹 & NLB**: **보안 그룹(Security Group)**은 인스턴스 수준에서 포트 번호(L4)를 기반으로 트래픽을 제어하며, **NLB(Network Load Balancer)**는 TCP/UDP 트래픽을 고성능으로 처리합니다.
- **L7 (응용 계층) - ALB**: Application Load Balancer는 HTTP/HTTPS 헤더와 같은 응용 데이터를 분석하여 정교하게 트래픽을 분산합니다.

**종합 요약**: AWS VPC 환경을 설계할 때 L3/L4 수준의 제어(NACL, 보안 그룹)를 이해하는 것은 보안의 깊이를 결정하며, L4와 L7 로드 밸런서의 차이를 아는 것은 서비스의 성능과 유연성을 결정합니다. OSI 모델의 이해는 더욱 견고하고 효율적인 클라우드 아키텍처를 설계할 수 있는 최고의 토대가 될 것입니다.

이 가이드를 통해 네트워크의 기본 원리를 이해함으로써, 더욱 견고하고 효율적인 클라우드 아키텍처를 설계할 수 있는 토대를 마련하셨기를 바랍니다.
